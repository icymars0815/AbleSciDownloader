# 常驻后台监控（2026-10-19，用户要求：需要监控求助的应助上传情况）

## 区分两种开关

| 开关 | 做什么 | 重启后 |
|---|---|---|
| **后台监控**（新） | 只读：按间隔后台同步“我的求助”，发现状态变化（有人应助/上传文件、被关闭、完结）即通知；会话失效时通知去登录 | **保持**（用户开了就一直开，跨重启） |
| 自动流水线（已有） | 下载/发布/采纳/拒绝等会改变状态或花积分的动作 | 仍按原设计：重启后回到关闭，需用户再次开启（防止无人值守时意外花积分） |

监控发现应助后：若流水线开着 → 交给流水线（下载、核对）；若没开 → 只通知。

## 常驻方式

- 服务本身已是无窗口 `pythonw`；关闭 App 窗口**不退出**服务（现状如此，需在 UI 明示“窗口关闭后仍在后台监控，可从托盘退出”）。
- **系统托盘图标**（pystray + Pillow，锁定版本加入 requirements-lock）：状态（监控中/暂停/需要登录/有待处理 N 条）、打开窗口、立即同步、暂停监控、退出。
- **Windows 通知**：有新应助、会话失效、需要人工处理（闸门锁定的条目、人机验证、最低悬赏提高）时弹系统通知；同一事件不重复通知。
- **开机自启**（可选，默认关）：在用户“启动”文件夹放快捷方式指向 `pythonw launcher.py --background`（不弹窗口，只起服务+托盘）；关闭时删除该快捷方式。不改注册表，不需要管理员权限。
- **单实例**：已有端口探测；再加锁文件，防止两个服务同时操作同一账户。

## 通知设置（设置 → 通知）

- **总开关**：一键开/关全部系统通知（关闭时托盘状态与 App 内记录照常更新）。
- **单项开关**（总开关开启时生效，各自默认值）：
  | 通知 | 默认 |
  |---|---|
  | 有人应助 / 上传文件 | 开 |
  | 下载完成并核对通过 | 开 |
  | 需要我处理（采纳/拒绝、核对未通过） | 开 |
  | 需要人工验证（出版社人机验证） | 开 |
  | 最低悬赏被提高、等我确认 | 开 |
  | 登录失效 | 开 |
  | 求助被关闭 / 到期退还积分 | 关 |
  | 开放获取下载成功 | 关 |
  | 同步失败（连续 3 次以上才提示） | 关 |
- 免打扰时段（可选，默认关）：时段内只记录不弹通知，结束后汇总一条。

## 轮询节奏（应助常在 5 分钟内上传）

不用固定间隔，而是按“是否有刚发布、正在等应助的求助”自适应：

| 情况 | 同步间隔 |
|---|---|
| 发布后 0–5 分钟仍在等应助（快速期） | **每 30 秒** |
| 发布后 5–15 分钟 | 每 1 分钟 |
| 发布后 15–60 分钟 | 每 3 分钟 |
| 其余等待中的求助 | 每 10 分钟（默认，可设 10–60） |
| 没有任何等待中的求助 | 每 30 分钟（只为发现账号状态变化），或用户关闭 |

- 热窗口只请求“我的求助”列表这一页，单请求、串行，仍遵守 ≥3 s 间隔与同时 1 个的限制；同一时刻多条在热窗口也只发一次请求。
- 快速期间隔（20–120 秒，默认 30）与快速期时长（1–15 分钟，默认 5）可在设置中调；可整体关闭热窗口改为固定间隔。用户反馈：有的应助约 1 分钟就到。
- 发现状态变为已应助后：立即通知；流水线开启时立即排队下载（不等下个同步周期）。
- 失败退避只作用于普通间隔；热窗口内失败则退回 3 分钟间隔，避免对网站连续重试。

## 资源与稳定性

- 无界面 Chrome 只在同步/下载时开启；空闲 5 分钟后关闭浏览器上下文释放内存（下次同步再开）。
- 监控间隔见“轮询节奏”；普通间隔失败指数退避（10→20→40 分钟，上限 60），成功后恢复。
- 电脑睡眠唤醒后：检测时间跳变，延迟 1 分钟再同步，避免网络未就绪即报错。
- 会话失效：不弹登录窗，只通知 + 托盘显示“需要登录”，暂停监控直到用户登录。
- 服务崩溃：launcher 下次启动自动恢复；监控状态与上次同步时间持久化在 queue.json。
- 日志进入日志模块（脱敏），托盘“打开日志与反馈”。

## 不变的约束

- 后台监控只读；不自动发布/采纳/拒绝/高速，除非流水线被用户在本次运行中开启且相应自动选项已确认。
- 同步只读本人求助列表页（及必要的详情页），遵守 ≥3 s 请求间隔。
