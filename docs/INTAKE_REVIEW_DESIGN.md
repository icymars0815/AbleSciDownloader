# 导入 → 免费源筛选 → 用户确认表 → 科研通求助（可视化流程）（2026-10-19，用户要求）

## 流程

1. **导入一批**：粘贴/文件导入后生成一个“批次”（batch_id，记录导入时间、条数）。
2. **免费源筛选**：批次内每条有 DOI 的条目自动跑 OA 查找/下载/核对（现有 oa_fetch，单并发、限速）。无 DOI 的条目标“无 DOI，无法自动筛选”。
3. **确认表**（筛选完成后自动弹出，也可从消息面板打开）：

   | 勾选 | 标题 | DOI | 免费源结果 | 建议 |
   |---|---|---|---|---|
   | ☑ | … | … | 非开放获取 | 发起科研通求助 |
   | ☐ | … | … | OA 已下载，核对通过 | 无需求助 |
   | ☐ | … | — | 无 DOI | 请补 DOI 或手动求助 |
   | ☐ | … | … | 需人工验证 / OA 核对未通过 | 先处理 |

   - 默认只勾选“非开放获取 / OA 下载失败”且有 DOI 的条目。
   - 表头汇总：当前积分、档位（<500 逐条 / ≥500 批量待适配）、预计悬赏 = 勾选数 × 默认悬赏（实际以页面最低值为准，可能更高）、闸门状态（<500 时有应助未处理则会排队等待）。
   - 按钮：「确认并开始科研通求助」「稍后再说」「导出表格 CSV」。
4. 只有用户确认过的条目带 `request_confirmed=true` + `request_batch_id`，才进入科研通 publish/prepare 步骤。未确认的 queued 条目流水线不会发布（即使开启自动发布）。自动发布开关的含义改为“确认表里确认过的条目自动逐条发布”。
5. 之后按现有流水线：发布（含弹窗二次核对）→ 监控 → 下载 → 核对 → 采纳/拒绝。

## 右下角消息面板（流程可视化）

- 固定在右下角的可折叠面板（不遮挡主操作；折叠后显示徽标：进行中 N / 需要你处理 N）。
- 按批次显示步骤时间线：
  `导入 12 条 ✓ → 免费源筛选 9/12 … → 等你确认（4 条需求助）● → 科研通求助 1/4 → 等应助 → 下载/核对 → 完成`
  每步显示状态（进行中/完成/等待你/出错）、计数和耗时；点击步骤展开该步条目列表与原因。
- 单条事件流（最近 50 条，按时间）：“OA：PLOS 下载成功并核对通过”“科研通：已发布求助《…》”“有人应助《…》，开始下载”等；需要用户处理的事件带操作按钮（打开确认表、采纳/拒绝、打开验证窗口）。
- 与系统通知共用同一事件源与开关（BACKGROUND_MONITOR_DESIGN.md），面板始终记录，通知按开关弹出。
- 原“处理记录”区并入此面板。

## 数据

- `store.data["batches"]`：{id, created, item_ids, phase: screening|awaiting_confirmation|requesting|monitoring|done, counts, confirmed_at}。
- 条目新增：`batch_id`、`request_confirmed`、`request_confirmed_at`。
- API：`GET /api/state` 带 batches 与面板事件；`POST /api/batch/confirm {batch_id, item_ids}`、`POST /api/batch/defer {batch_id}`。
- 无科研通登录时：确认表仍出现，「确认并开始科研通求助」变为「登录科研通后可求助」。
