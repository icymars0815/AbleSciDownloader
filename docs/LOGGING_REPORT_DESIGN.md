# 日志与错误报告模块 + 免费声明 / GitHub 地址（2026-10-19）

## 日志

- 结构化日志写入 `data/logs/kytdl-YYYYMMDD.log`（JSON lines），按天分文件、保留 14 天（只滚动本模块自己的日志文件，不清理 data/ 其他内容）。
- 记录：时间、模块、动作、结果、错误类型、精简堆栈（仅本项目文件帧）、App 版本、git 提交短哈希（若可得）。
- **写入前脱敏**（统一 `redact()`，单元测试覆盖）：邮箱、密码字段、API Key（sk-…、Bearer …）、Cookie/Set-Cookie、URL 中的 token/key/sig 参数、Windows 用户目录名（`C:\Users\<name>` → `C:\Users\<user>`）、科研通求助 id 可保留。
- 现有 `store.event` 用户事件保留不变；日志是开发诊断用的另一层。

## 错误报告流程（设置 → 日志与反馈；任务出错的提示里也有入口）

1. 列出最近错误（时间、动作、简述）。
2. “生成报告”：汇总所选错误 + 最近 50 条事件 + 环境信息（Windows 版本、Python、Chrome 是否存在、依赖版本、App 版本），全部经过 redact，**先预览全文**。
3. AI 开启时：“让 AI 分析”——逐次确认后发送预览中的脱敏报告，返回“可能原因 / 建议用户操作”，只显示，不执行任何操作，不改设置。AI 关闭时该按钮禁用并提示需开启 AI。
4. 仍未解决：“保存报告”（另存为 .md 到用户选择位置/下载）+ “打开 GitHub Issue”（新标签页打开 `<repo>/issues/new?title=…&body=…`，正文只放简短说明并提示用户把保存的报告文件拖入 issue；App 不自动提交、不需要 GitHub 登录信息）。
5. 提示语：提交前请再检查报告中没有个人信息。
