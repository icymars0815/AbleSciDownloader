## 单篇求助（DOI 为输入源）的真实流程

1. 打开 `/assist/create`，在 `#onekey` 输入 DOI（只用 DOI；无 DOI 的条目不进入自动发布，交给用户）。
2. 点 `button.onekey-search`「智能提取文献信息」→ ajax `onekey-query`；可能返回 `job_uuid` 排队，页面每 1.5 s 轮询 `paper-lookup-status`，最长 45 s。
3. 弹出识别结果（layer 弹窗）：标题、相似度（<50% 页面会提示“偏低，建议您手动核实”）、DOI、期刊、作者、发表时间、类型、最低悬赏（疑难数据库 >10；学位论文 50；书籍 200；书籍章节 30）。用户确认后表单被填充。
4. 可能出现「快捷提示」layer.confirm：『直接提交』/『返回修改』。
5. 「立即发布」`#form-submit-btn` → 前端检查悬赏 ≥ 最低值 → ajax `/assist/check-before-assist-create`：
   - code 0：直接提交，跳转到求助详情 `res.data.url`；
   - code 2：「确认提示」弹窗『仍然提交』/『返回修改』，**仍然提交可能把悬赏自动提高到出版社最低积分**；
   - code 1：错误提示。
6. 默认：悬赏 10 分（最低 10）；自动关闭默认 +5 天（可选 1 小时–10 天，到期无人应助退还积分）。

## 程序必须遵守的二次核对

- 第 3 步弹窗出现后，程序抓取弹窗中的标题/DOI/相似度/最低悬赏，与本地条目（DOI 精确一致；标题与 OpenAlex 记录相似度 ≥ 0.90）比对：
  - 任一不一致、相似度 <50、类型不是期刊论文、或最低悬赏 > 用户设定的“自动发布最高悬赏”（默认 10）→ **停止，交给用户**（stage attention，附弹窗内容截图与字段）。
  - 全部一致 → 才继续。
- 最低悬赏档位**不写死**（页面脚本可见 10/30/50/200 及疑难数据库的出版社专属值，用户反馈还有 100 等），一律从弹窗/页面实际读取数值。
- 设置 → 流水线「最低悬赏被提高时」：
  - **每次都问我**（默认）：第 3 步识别出的最低悬赏 > 当前悬赏，或第 5 步出现 code 2「确认提示」→ 停止交给用户，显示实际所需积分。
  - **自动接受，最高 N 分**（N 由用户填写，10–500，开启需确认规则）：所需积分 ≤ N 且 ≤ 当前余额 − 保留积分（默认保留 0，可设）时自动接受；否则仍交给用户。
  - code 2 弹窗内容若不是“最低悬赏提高”这一类（例如重复求助、文献信息冲突），无论设置如何都交给用户。
- 悬赏只取 max(用户默认悬赏, 页面实际最低值)，且受上面上限约束；发布前读取页面“您当前有 N 积分”刷新档位并重查闸门；每次实际花费记录到条目 `publish_action.point` 与事件中。
- 结果判定：跳转到 `/assist/detail?id=…` 才算 confirmed；其他情况 uncertain，不重试。
- 手动发布按钮：在 App 内先展示将提交的 DOI/标题/悬赏/自动关闭时间，用户确认后执行同样流程；遇到上述停止条件同样交给用户。

## 并发与请求节奏（减轻网站压力）

- 科研通：全部操作经 BrowserAgent **串行，同时最多 1 个**；任意两次页面导航/接口请求间隔 ≥ 3 s（可设 3–30 s）；同步节奏按 BACKGROUND_MONITOR_DESIGN.md 自适应（热窗口每 1 分钟、普通 ≥10 分钟）；发布之间至少间隔 60 s；下载同时只 1 个。
- 每小时最多自动发布 N 篇（默认 10，可设 1–30），超出则流水线等待。
- OA 源：同时只 1 个条目在查找；同一主机请求间隔 ≥ 1 s；429 记录后本条跳过该源，不重试。
- 所有上述值可在 设置 → 下载规则 / 流水线 中调整，但不能低于下限。
