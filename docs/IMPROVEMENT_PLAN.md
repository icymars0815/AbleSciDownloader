# 改进总规划（2026-10-19）

## 一、科研通下载体验（重点）

依据：2026-10-19 真实下载 14.9 MB 文件，3 条普通线路速度 0.5–24 KB/s、每 30–60 秒卡顿、换线从 0 重来，13 分钟仍未完成。

| # | 改进 | 解决的问题 | 前提/风险 |
|---|---|---|---|
| D1 | **下次真实下载时只读观察**页面网络请求，核实是否支持 HTTP Range（用户记得不支持；ZMoe2024/ablesci-toolkit 文档称普通节点支持） | 决定 D2 | 只观察，不改请求、不多开连接 |
| D2 | **用户裁定：D1 属实就做断点续传**——卡顿/换线后从已收到字节继续；仍单连接、不分片并发；续传前后校验大小，最终仍做 %PDF 与核对 | 换线/卡顿浪费进度 | 仅用户本人会话、本人求助文件 |
| **D3（核心）** | **三线路选最快**：开始时每条线路试 15 秒（可设 5–60 秒），按实测速度选最快的一条下完；记录各线路在不同时段的历史速度，有近期历史时直接从历史最快的开始并缩短试测；所选线路中途明显变慢（低于另一条历史速度的一半且持续 60 秒）才考虑切换 | 只能在 3 个服务器里选最快的 | 多 15–45 秒试测；可在设置关闭 |
| D4 | **下载前先报文件大小与预计用时**（页面有“已接收 X / 总大小”），预计超过上限时按高速档位（关闭/智能/强制）给出建议 | 不知道要等多久 | 无 |
| D5 | **进度可视化**：条目进度条、当前线路、速度、剩余时间；右下角消息面板同步；完成后系统通知 | 下载是黑盒 | 依赖消息面板（进行中） |
| D6 | **收到应助立即下载**（24 小时删除）+ 闲时队列：大文件（可设阈值，如 >10 MB）且当前速度很慢时，可选择“闲时再下”，在用户设定的时段自动下载，但不晚于删除时间前 2 小时 | 白天慢、文件会被删 | 闲时段由用户设定 |
| D7 | **保留原文件名**，存 `downloads/{条目}/原名.pdf`；完成后“打开 PDF / 打开所在文件夹”按钮 | 规则要求不改文件名；找文件不便 | 迁移旧文件只做记录不移动 |
| D8 | **失败说明更具体**：区分“网站卡顿”“线路报错”“登录失效”“文件已删除”，并给下一步建议（换时段、开智能高速、去官网看） | 报错难懂 | 无 |
| D9 | **同一文件只下一次**：已有本地副本的条目不重复下载；已扣高速积分的文件记录在案，不重复付费 | 重复扣分 | 已部分实现 |

执行顺序：D3 → D4/D5/D7/D8（与界面任务合并）→ D6 → D9 收尾；D3 用下一次真实下载验收。
